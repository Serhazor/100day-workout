# 100 дней: свой вес → гиря 24 кг

Личный трекер на 100 дней подряд. Тренировка каждый день: четыре нагрузочных, три лёгких.
Пять блоков по три недели — от упражнений с собственным весом к гире 24 кг. Турник не нужен.
С недавнего времени сюда же встроен дневник питания: продукты, приёмы пищи, разбор чека и
ИИ-подсказка по КБЖУ — раньше это был отдельный прототип, теперь это одно приложение.

- `index.html` — всё приложение: план на каждый день, отметки, вес с графиком, дневник питания
  и библиотека продуктов, макросы, печатные листы
- `planner.pdf` — те же 100 дней на бумагу, по неделе на страницу, с пустыми клетками под ручку
- `api/state.js` — чтение и запись состояния в Neon
- `api/nutrition.js` — разбор чека и оценка КБЖУ продукта через Anthropic API (нужен свой ключ, см. ниже)
- `schema.sql` — одна таблица

Старт: 5 сентября 2026. Дата меняется внизу приложения, расписание пересчитается само.

## Развёртывание

### 1. Neon

Создай проект на neon.tech, выполни в SQL Editor содержимое `schema.sql`,
скопируй строку подключения (Connection string, вариант с пулером).

### 2. Vercel

Импортируй репозиторий. Фреймворк — Other, build command оставь пустым:
`index.html` отдаётся как статика, `api/` подхватывается автоматически.

Переменные окружения (Settings → Environment Variables):

| Имя | Значение | Обязательна? |
|---|---|---|
| `DATABASE_URL` | строка подключения из Neon | да |
| `APP_KEY` | любая длинная случайная строка, придумай сам | да |
| `ANTHROPIC_API_KEY` | ключ с console.anthropic.com | только для ИИ-подсказки и разбора чека |

`APP_KEY` — это пароль к твоим данным и одновременно ключ для `/api/nutrition`: без него ни
синхронизация, ни ИИ-функции не заработают, даже если `ANTHROPIC_API_KEY` задан. В репозиторий
он не попадает и в коде приложения его нет: ты вводишь ключ один раз в самом приложении, он
остаётся в браузере.

Сгенерировать `APP_KEY` можно так:

```bash
openssl rand -base64 24
```

`ANTHROPIC_API_KEY` — необязателен. Без него всё приложение работает как обычно, кроме двух
кнопок: «ИИ-подсказка» в карточке продукта и «Добавить по чеку» в дневнике питания — они
покажут понятную ошибку вместо того, чтобы падать. Каждый вызов этих кнопок — это один
недорогой запрос к Claude Haiku, оплачивается с твоего аккаунта Anthropic.

### 3. Включить синхронизацию

Открой задеплоенный адрес, пролистай вниз до блока «Синхронизация между устройствами»,
вставь `APP_KEY`, нажми «Подключить». Состояние должно смениться на «в порядке».
Повтори на втором устройстве с тем же ключом и тем же профилем.

На телефоне добавь страницу на домашний экран — откроется без адресной строки, как приложение.

## Питание

Вкладка «Питание» — дневник на текущий день: заносишь продукты, видишь итог калорий и
макросов против целей блока (они те же, что были в справочной таблице раньше — просто теперь
считаются автоматически). Вкладка «Продукты» — библиотека: то, что один раз занесено, потом
ищется и добавляется в один клик на любой день программы.

Три способа занести продукт:

- **Вручную** — «Новый продукт» в «Продукты» или «+ Добавить продукт» на «Питание».
- **ИИ-подсказка** — кнопка рядом с названием в карточке продукта: печатаешь «морковь»,
  получаешь оценку КБЖУ, при этом свои уже введённые цифры не перезаписываются.
- **По чеку** — фото или текст чека, ИИ выделяет позиции и оценивает КБЖУ; список всегда
  можно поправить перед сохранением, ничего не пишется в библиотеку без подтверждения.
- **Списком** — «Импорт списком» в «Продукты»: вставляешь JSON-массив (кнопка «Скопировать
  образец» даёт формат), видишь превью с ошибками по каждой строке перед импортом.

Библиотека продуктов и приёмов пищи не сбрасывается кнопкой «Сбросить прогресс» — она чистит
только отметки тренировок, вес и дневник питания по дням, а не то, что ты один раз занёс.

## Как устроена синхронизация

Данные пишутся в localStorage мгновенно, на сервер уходят через секунду после изменения.
Без сети отметки всё равно сохраняются и уедут при следующем открытии.

При загрузке приложение сравнивает `updatedAt` локальной и серверной версии и берёт свежую.
Разрешение конфликтов — последняя запись побеждает. Для одного человека с двумя устройствами
этого достаточно; если в один день отмечаться параллельно с телефона и ноутбука,
часть галочек может потеряться. То же самое касается дневника питания.

Поле `profile` позволяет держать в одной базе несколько наборов данных — например,
если по этой программе пойдёт кто-то ещё.

## Локальный запуск

```bash
npm install
npx vercel dev
```

Нужны те же три переменные (третья опциональна) — положи их в `.env.local`.

## Структура данных

```json
{
  "start": "2026-09-05",
  "updatedAt": 1757052000000,
  "done": { "12:3": true },
  "weights": { "1": 105.0, "8": 102.9 },
  "foods": [
    { "id": "id-...", "name": "Морковь", "servingLabel": "1 средняя (61 г)",
      "calories": 25, "protein": 0.6, "carbs": 6, "fat": 0.1, "favorite": false, "useCount": 3 }
  ],
  "meals": [
    { "id": "id-...", "name": "Завтрак спортсмена", "items": [ { "foodId": "id-...", "name": "…", "qty": 2, "calories": 50 } ] }
  ],
  "foodlog": {
    "12": { "entries": [ { "id": "id-...", "foodId": "id-...", "name": "Морковь", "qty": 1, "calories": 25, "protein": 0.6, "carbs": 6, "fat": 0.1 } ] }
  }
}
```

Ключ в `done` — это `день:номер упражнения`. Ключ в `weights` и `foodlog` — номер дня программы
(1–100), а не календарная дата: так же, как вес, дневник питания привязан к дню программы,
чтобы прогресс не зависел от того, когда именно открыт день.

Всё по-прежнему лежит одной JSON-строкой в той же таблице `state` — под сто дней дневника
питания у одного человека это по-прежнему единицы-десятки килобайт, отдельные таблицы не нужны.
